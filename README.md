## 🧩 Технические характеристики

*   **Архитектура:** Реализован паттерн **API Client / Service Layer**. Бизнес-логика вынесена в клиенты, тесты остаются «тонкими» и читаемыми.
*   **Параметризация:** Тесты параметризованы по платформам (`core`, `platform_a`, `platform_b`), а фикстуры автоматически прогоняют сценарии на **трех разных контрагентах** для повышения покрытия.
*   **Работа с данными:** Настройки вынесены в `.env` и типизированы через `pydantic-settings`, что гарантирует безопасность и гибкость конфигурации.
*   **Логирование и отладка:** Настроен централизованный логгер с **маскированием чувствительных данных** (токены, пароли) и ротацией логов.
*   **Контекст тестов:** Реализован автоматический инжектор контекста (`autouse` fixture), который при падении теста мгновенно показывает, на каком именно контрагенте и счете произошла ошибка.
*   **Инфраструктура:** Проект готов к запуску в CI/CD (поддержка `pytest-xdist` для параллельного запуска и генерации отчетов Allure).
*   **Стек:** Python 3.13, `pytest`, `requests`, `pydantic-settings`, `Allure`.

> 🔒 **Примечание для портфолио:** Код представляет собой демонстрационную версию. Все реальные эндпоинты, данные контрагентов, UUID и бизнес-логика заменены на обобщенные плейсхолдеры для соблюдения NDA корпоративного клиента.
